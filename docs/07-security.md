# Security

Untrusted input: mod archives, mod metadata/descriptors, shared playset and preset files, Workshop page data, and anything another website tries to send to our local port.

1. **Local server**: binds 127.0.0.1 only; rejects any `Host` that is not `127.0.0.1`/`localhost` (DNS rebinding) and cross-origin POSTs; request bodies are size-capped (413 from the header alone); bodies must be JSON objects; uploads stream to disk.
2. **Browser hardening**: strict CSP (`script-src 'self'`, no inline script, `frame-ancestors 'none'`), `nosniff`, `no-store`, static files served from a fixed allow-list, never from a request path. All dynamic text is HTML-escaped.
3. **Archives**: no `..`, absolute/drive paths, reserved names, alternate streams or symlinks; scripts/executables rejected; caps on entry count, total size and compression ratio; real bytes are counted while extracting; extraction goes to a staging dir and is moved into place only after validation.
4. **Process launch**: no shell, ever. The game is spawned from an argument list; extra arguments must match `^[-/][A-Za-z0-9_.:/=-]{1,63}$` and cannot set `-applaunch`/`-exec`; Steam URL arguments are percent-encoded. `steamcmd` is run from an argument list with a validated account name and numeric ids only, with a timeout, and never receives a password from us (it must already be logged in).
5. **Imported data**: playset files, presets and legacy files are schema-checked, size-capped, every field validated; a failed import creates nothing; a playset for another game is refused. Preset ids are `^[a-z0-9][a-z0-9_.-]*$` so a preset can never be written outside its folder. Broken preset/legacy files are skipped, not fatal.
6. **File writes** are confined to the app data dir, the user's `mod` folder, the game's load file and the save folder link. Uninstall only touches paths inside `<user dir>/mod`. Writes are atomic; a rolling `.bak` of the playset file is kept; a damaged playset file is never overwritten.
7. **Privacy and network**: the network is touched only on an explicit user action: `--fetch-logo`, `--check-update`, *Check for updates now*, the *Check for updates when the manager starts* setting (**off by default**), *Open in Steam* (asks the local Steam client to show a page, no request from us) and *Download with steamcmd* (steamcmd talks to Steam). Update checks: HTTPS to `api.github.com` only, 10 s timeout, 1 MB cap, at most one request per 10 minutes, nothing downloaded or installed (the UI links to the release page; links not under this repo's `github.com` URL are replaced; release notes are shown as text). An optional `MODMANAGER_GITHUB_TOKEN` (private repo) is read from the environment, sent only to `api.github.com`, never stored or returned. Logo download: HTTPS, host must end in `.steamstatic.com`, size-capped, must be a real PNG.
8. **Logos and art**: game artwork is never stored in this repo. It is read from the user's own Steam cache or install, a file they supply, or downloaded by them with `--fetch-logo`. Only image types are served, from one fixed file per game.
9. **Symlinks**: the scanner never follows links, so a mod cannot make it read outside its folder.

Known gaps: CI actions are pinned to major tags, not commit SHAs (TODO); no dependency audit is needed (stdlib only) but PyInstaller is a build-time dependency; the server has no authentication because it only answers loopback (anything running as the same user on the same machine can talk to it, as with any local dev server).
